# Glossary Conventions

This project maintains a **hierarchical glossary**.

## Core rule
Organize the glossary by:
1. **natural grouping**
2. then **alphabetical order within each group**

This means the glossary is treated as a lightweight concept hierarchy, not merely a flat alphabetical list.

## Why
A graph theory learner benefits more from seeing:
- related terms together
- structural clusters
- theorem families
- algorithm families
- representation families

than from seeing one long undifferentiated list.

## Maintenance rule
When a new term appears during the lesson plan:
- add it to the most natural existing group
- alphabetize it within that group
- if the group becomes too broad, split the group into subgroups

## Example grouping pattern
- Core foundations
- Movement and reachability
- Trees and spanning structures
- Directed graphs
- Eulerian and Hamiltonian themes
- Bipartite, matching, and flow
- Coloring and independence
- Matrix and algebraic terms
- Algorithms and optimization
- Named graph families
- Theorem and structural terms

## Escalation rule
If a section becomes crowded, use subgroup headings such as:
- group by <natural grouping>
- then alphabetical

This is the standing project convention.
